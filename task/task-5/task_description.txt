task_description: |
  Analytics dashboard is painfully slow with big datasets. Like 10-15 seconds to load when a 
  workspace has 10,000+ tasks. Users are not happy about this lol.
  
  Performance issues:
  - No database indexes so every query does full collection scans
  - Making like 20 separate queries instead of using aggregation pipelines  
  - No caching at all
  - analyticsService is a mess - needs refactoring
  
  Solutions needed:
  Add indexes on the fields we query all the time - status, assignee, dueDate, workspace. Test 
  that these don't slow down writes though.
  
  Use MongoDB aggregation pipelines instead of multiple queries. Should be able to get all the 
  dashboard stats in one or two queries max.
  
  Redis cache with like 5 minute TTL. Analytics don't need to be real-time so caching makes sense.
  Aim for 80%+ cache hit rate.
  
  Refactor analyticsService to batch queries together. Less round trips = faster.
  
  Pagination for when results are huge.
  
  Add monitoring so we can see which queries are slow (>100ms) and optimize them.
  
  Target: dashboard under 1 second load time. And don't blow up memory usage!
